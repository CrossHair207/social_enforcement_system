# Schema management

The application creates its schema from the SQLAlchemy models in
`database/models.py` at start-up (`core.database.init_db`). On a fresh database
this is all that is required, for SQLite and PostgreSQL alike.

## Initialising a PostgreSQL database

1. Create the database and role:

   ```sql
   CREATE ROLE sems LOGIN PASSWORD 'change-me';
   CREATE DATABASE sems OWNER sems;
   ```

2. Point `DATABASE_URL` at it in `.env`:

   ```
   DATABASE_URL=postgresql+psycopg://sems:change-me@localhost:5432/sems
   ```

3. Create the tables:

   ```bash
   python database/migrations/init_postgres.py
   ```

   The script refuses to run against SQLite and prints the target host so an
   operator can confirm they are pointed at the intended database. It is
   idempotent: existing tables are left untouched.

## Changing the schema later

`create_all()` only creates missing tables; it does not alter existing ones.
Once the system holds real cases, introduce Alembic before changing a model:

```bash
pip install alembic
alembic init migrations_alembic
# set sqlalchemy.url from the DATABASE_URL environment variable
alembic revision --autogenerate -m "describe the change"
alembic upgrade head
```

Review every autogenerated migration before applying it: column drops and type
changes can destroy evidence metadata.

## Backups

Back up both the database **and** the evidence directory (`DATA_DIR/evidence`).
A case file without its evidence is not usable, and evidence hashes only prove
integrity against the original files.
